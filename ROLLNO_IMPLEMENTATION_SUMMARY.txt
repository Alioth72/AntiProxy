================================================================================
TECHNICAL BENEFITS OF THIS IMPLEMENTATION
================================================================================

✅ EXACT IDENTIFICATION
   - Roll numbers are unique (students.roll_no has UNIQUE constraint)
   - No ambiguity with similar names

✅ CLASS-SCOPED RECOGNITION
   - Face-API only searches students enrolled in that specific class
   - Prevents "Shubhank from Class A" matching "Shubhank from Class B"
   - Significant performance improvement (search only ~30-50 students vs all 48+)

✅ ELIMINATES NAME MATCHING ERRORS
   - No more fuzzy string comparisons
   - No case sensitivity issues
   - No partial name confusion

✅ FASTER MATCHING
   - O(1) dict/hash lookup by roll_no instead of O(n) name string comparison
   - Teacher app can use firstWhere(s => s.rno == personId) for instant match

✅ HANDLES NAME CHANGES
   - If student name corrected in DB, face remains linked to roll_no
   - No need to re-upload photos after name corrections

✅ BETTER AUDIT TRAIL
   - Clear link: face embedding -> roll_no -> student UUID
   - Can track: "Which roll_no was recognized at timestamp X?"

✅ BACKWARD COMPATIBLE
   - Falls back to name matching if personId is null
   - Supports legacy enrollments without roll_no
